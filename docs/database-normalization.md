# 数据库执行配置与账务字段收敛（0044）

这轮在 V2 基础上删除 23 个重复字段，代码与数据库必须同时升级。

| 表 | 当前职责 / 删除内容 |
| --- | --- |
| users | 只保留用户身份、权限、邀请和状态；删除积分余额及 5 个 Stripe/订阅字段 |
| billing_accounts | 积分余额、账本基线和订阅信息的唯一权威来源 |
| llm_model_configs | 只保存名称、角色开关、默认选择、可用性及 current_version_id；删除 8 个执行参数字段 |
| llm_model_config_versions | 唯一执行配置来源；修改参数、密钥和价格时追加不可变版本 |
| analysis_jobs | 只保留 Quick / Deep 版本引用与配置可信状态；删除 9 个模型名称、配置 ID、供应商地址和 JSON 快照字段 |
| analysis_job_legacy_configs | 仅保存无法建立可靠版本关联的旧任务原始证据；不是执行配置，也不为新任务写入 |

报告列表和模型名称通过版本关联读取，网页 DTO 仍保留可读模型信息。旧任务缺少可靠版本时，用户须明确选模型才能继续；不会偷偷替换成当前配置。换模审计中的历史证据和实际调用中的价格快照用于追溯，不能视作可删除的重复执行配置。

## 数据迁移

1. 备份数据库与环境配置，在临时数据库还原并演练。
2. `initialize-database.cjs` 先运行凭据预检查，将旧模型明文密钥转为加密信封；密钥不可解密时停止升级，不输出凭据。
3. 0044 在事务中核对旧用户账务与 billing_accounts 完全一致；不一致就中止，不择一覆盖。
4. 将每个模型当前参数固化为版本，保留所有历史版本。缺密钥的占位配置使用 NULL 密钥版本并停用，不伪造密钥。
5. 将无法可靠版本化的任务配置移入历史证据表，再删除重复列。已有版本引用、任务身份、报告、账本和调用记录保持。
6. 启动匹配版本的应用，验证登录、列表、报告和账务。

这是结构收缩迁移，旧应用不能继续运行在新结构上；应用写入必须停止后再应用。恢复时须成套恢复数据库与原应用，保留迁移后新写入，不能仅回退代码。直接运行 Drizzle SQL 前，必须先执行凭据预检查；推荐统一使用初始化工具。

旧库首次导入工具 `migrate-legacy-database.ts` 只接受 0043 兼容结构。未来重新导入必须先在临时库还原旧目标备份、导入并演练，然后升级；禁止直接重导到已收敛的业务库。

## 模型调用费用保护

两张模型调用表的终态记录禁止普通同步覆盖。同步只更新 running 行，第一次进入终态时允许保存最终结果；终态重放保持原值。缺失用量继续保持未知，不推测补齐。

DBA 可调用 `public.correct_model_call_usage(table_name, call_id, admin_user_id, reason, patch)` 做受控更正（以迁移中函数签名为准）。函数默认撤销 PUBLIC 执行权限；如需委派，只授予独立更正角色，不能给普通业务角色。更正校验活跃超级管理员、原因、字段白名单和非负值，并在同一事务保存前后值审计；分析调用更正会更新任务 Token 汇总。

`stockdepth_internal` 仅存事务内更正许可，不是业务表，普通角色没有访问权限。数据库所有者本身具有修改触发器的权限，因此其凭据属于受信运维边界，不能发给终端用户。

CI 覆盖新库初始化、旧库升级、账务一致性、版本不可变、历史数据保留、终态重放、受控更正及 Worker 续跑。
