# 模型额度耗尽后的默认模型与 Job 恢复

- 明确的供应商余额/额度耗尽证据写入 `llm_model_configs.unavailable_reason = quota_exhausted` 和 `unavailable_at`；普通限流、网络错误和未知 HTTP 400 不会因此封禁模型。
- 不可用默认模型取消 `is_default`，原子选出可用的新默认模型；保留手动启用开关。默认标记变更不改模型配置版本，以便同时运行的任务仍能正确归属额度事件。
- Worker 在启动前、每次同步调用用量后检查当前任务快照的模型可用性，不再等进程退出或报告一致后才处理额度失败。
- 先停止旧 runner，再在 Job 所有权和租约保护下换模、保存加密历史快照、重新入队；继续沿用 run ID 和 Checkpoint，不重复扣网站分析额度。报告、历史调用及原价格快照保留。
- 仍可用的 Quick/Deep 角色保留原模型；受影响角色优先使用支持该角色的默认模型，否则选第一个可用且角色匹配的模型。
- 每个 Job 的换模历史达到 3 条后不再自动切换；已有手动换模同样计入该保守上限。无候选或达到上限时，任务以明确原因失败，允许后续手动处理。不会自动重启部署前已失败的任务。
- 每次恢复按最近换模记录起算该次执行的超时，保留任务最初开始时间用于展示。

验证：隔离 PostgreSQL schema 中验证默认模型持久化、额度/限流分类、配置版本隔离、自动与手动换模、重复回调、租约所有权、三次上限、无候选、原报告/费用/额度保留。Worker 模拟 API 在进程仍报告 running 且报告版本不一致时返回额度错误，验证任务自动换模并重新入队；测试不访问模型供应商。
