# 页面跳转响应优化

本轮在 dev 上完成，并重新构建运行服务。

- 工作台和管理导航改用共享 NavigationLink，使用 Next 15 的 useLinkStatus 展示当前目标链接的等待反馈。保留 Next 原生路由取消、预取和错误处理，不通过手写定时器假装页面完成。
- 工作台、分析页和管理页新增 loading.tsx，等待服务端数据时显示轻量加载界面，保留可操作的侧栏；使用默认部分预取，不在后台一次性加载所有管理页的数据。
- 工作台导航使用 Button asChild，让一个链接承担点击和键盘行为，移除链接内部嵌套按钮；选中项使用 aria-current。移动侧栏只在实际客户端导航时关闭，修饰键打开新标签不改变当前菜单。
- Buy Credits 改用内部 Link，避免整页刷新。
- 账户设置页去掉表单内不参与数据挂起的 Suspense。浏览器实际打开该页曾出现 React #418：服务端插入的 Server Action 隐藏表单字段与客户端 Suspense 边界不一致，触发客户端重新渲染。移除冗余边界后，开发浏览器检查未再出现该错误，表单动作及验证保留。
- 管理任务详情的模型费用、模拟交易费用和报告元数据查询改为 Promise.all，并继续在鉴权、任务存在性检查之后执行；用户过滤和精度计算未改变。

没有增加跨用户服务器缓存，没有缓存/放宽鉴权，也没有用预取触发分析、下单或其他写操作。

验证包含生产构建及类型检查、五种屏幕尺寸下的导航与侧栏回归、组合报表页面回归、四个管理页面的浏览器回归。新增只读诊断脚本 scripts/diagnostics/navigation-latency.cjs：限定 loopback，使用当前本地账户读取页面，不输出会话令牌和页面内容；分别观察正常请求和人为延迟 RSC 请求时的点击反馈与内容到达时间。诊断仅为本地单次观测，不代表生产 SLA，也不声称所有数据查询会瞬间完成。

运维：先确认无排队/运行中的分析任务，再重启 API、analysis Worker 和 market Worker；Web 生产构建完成后重新启动。原 Web 构建留在 var/web-build-before-navigation 供本次切换回退。未启动原本未运行的自动交易 Worker。

最终生产浏览器检查：设置页 → 分析页，正常请求一次观测的点击反馈约 8ms、内容就绪约 368ms；人为增加 350ms RSC 延迟时，反馈约 3ms、内容就绪约 794ms。两次都没有浏览器渲染异常、嵌套交互元素或残留等待指示。数值仅为本机观测，不构成优化前后倍率对比。API 鉴权挑战正常，Web 登录页返回 200，四个已启用服务均运行。
